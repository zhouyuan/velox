==================
Flink Query Runner
==================

Introduction
------------

The Flink Query Runner uses Apache Flink as the reference database of the
expression fuzzer. It verifies the Velox Presto functions against their Flink
SQL counterparts, which shows how closely Velox matches Flink semantics, e.g.
for engines that run Flink SQL on top of Velox. Flink Query Runner is designed
to run against Flink-1.19.

How It Works
------------

Since Flink 1.16, the Flink SQL Gateway exposes a REST API that executes SQL
statements in a Flink session and returns results as JSON. The Flink Query
Runner submits queries and fetches results through it. The steps for this
process are as follows:

1. Open a Flink session through ``POST /v1/sessions``. The session runs queries
   in batch mode with ``table.local-time-zone`` taken from the Velox query config
   ``session_timezone`` (UTC if not set, as in Velox).
2. Convert the Velox plan, a projection over the fuzzer-generated input rows,
   into Flink SQL. The input rows are inlined as typed literals in a ``VALUES``
   clause, so the Flink cluster does not need to read files written by Velox,
   e.g.

   .. code-block:: sql

       SELECT (`c0` = `c1`) AS `p0`, `row_number` AS `p1`
       FROM (VALUES (CAST(1 AS INT), CAST(2 AS INT), CAST(0 AS BIGINT)))
           AS t(`c0`, `c1`, `row_number`)

   Velox Presto function names are mapped to Flink SQL where they differ, e.g.
   ``eq(a, b)`` to ``a = b``, ``length(s)`` to ``CHAR_LENGTH(s)`` and
   ``strpos(s, t)`` to ``POSITION(t IN s)``. BIGINT arguments that Flink takes
   as INT, e.g. the start of ``substr``, are clamped to the INT range. Other
   functions keep their names.
3. Submit the statement through ``POST /v1/sessions/{session}/statements``.
4. Fetch the results through
   ``GET /v2/sessions/{session}/operations/{operation}/result/{token}?rowFormat=JSON``
   until the end of the stream.
5. Convert the JSON rows into Velox vectors of the plan output type for the
   comparison with Velox's results.

A query is reported as unsupported, and not verified, if:

* the expression has no Flink counterpart, e.g. ``try``;
* an input value cannot be represented in Flink, e.g. a date outside the years
  1 to 9999;
* Flink rejects the query while parsing or validating it, e.g. because Flink
  has no function of that name or it takes other argument types;
* the Flink result type differs from the Velox one, e.g. ``md5`` returns
  VARBINARY in Presto and STRING in Flink.

These show where Presto and Flink functions differ in name or signature, not
where Velox computes wrong results, so they do not fail the fuzzer.

Usage
-----

To use the Flink Query Runner, you will need to deploy an executable Flink and
start a local cluster and the SQL Gateway with below command.

.. code-block::

    export FLINK_HOME=/path/to/flink-1.19.2
    bash scripts/ci/flink/start-flink.sh

The gateway is started at `http://localhost:8083`. Then run the expression
fuzzer of the Presto functions with Flink as the reference database.

.. code-block::

    _build/debug/velox/expression/fuzzer/velox_expression_fuzzer_test \
        --flink_gateway_url=http://localhost:8083 --duration_sec 600 \
        --velox_fuzzer_enable_complex_types=false \
        --logtostderr=1 --minloglevel=0

Only scalar types are supported, so disable complex types. ``cast`` is not
among the special forms generated by default, as Velox casts follow Presto
semantics while Flink casts follow Flink's. Pass
``--special_forms=and,or,cast,coalesce,if,switch`` to include it. Timestamps
are not adjusted to the session timezone, as Flink TIMESTAMP has no timezone.

The SQL translation is tested by ``flink_sql_test``. ``flink_query_runner_test``
tests the conversion of results without Flink, and the runner against the SQL
Gateway in its ``DISABLED_`` tests: run them with
``--gtest_also_run_disabled_tests``, and set ``FLINK_GATEWAY_URL`` if the
gateway is not at `http://localhost:8083`.

Nightly Run
-----------

``.github/workflows/flink-fuzzer.yml`` builds the fuzzer, starts Flink with
``scripts/ci/flink/start-flink.sh`` and runs the fuzzer against it for an hour
every night. It can also be started manually with a ref, duration and seed.
Failures are reported as GitHub issues labeled ``flink-fuzzer`` by
``scripts/ci/flink/fuzzer-report.sh``: the issue title holds the failure
reason, and a failure whose reason matches an open issue is added to it as a
comment. The issue links to the run artifacts, which contain the repro files
and the tail of the fuzzer log, and gives the seed to reproduce the failing
iteration.

Known differences between Presto and Flink semantics go into
``skipFunctionsFlink`` in ``velox/expression/fuzzer/ExpressionFuzzerTest.cpp``.

Limitations
-----------

* Only scalar types are supported: ARRAY, MAP, ROW, interval and Presto custom
  types such as TIMESTAMP WITH TIME ZONE are not verified.
* Functions whose unit argument is a keyword in Flink, such as ``date_trunc``,
  are only verified for constant units.
