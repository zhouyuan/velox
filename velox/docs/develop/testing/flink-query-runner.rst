==================
Flink Query Runner
==================

Introduction
------------

The Flink Query Runner is a tool designed to facilitate the testing of the
Flink SQL functions in Velox (``velox/functions/flinksql`` and
``velox/experimental/stateful/udf``). It is used as the reference database of
the Flink Expression Fuzzer, which generates random expressions over the Flink
functions, evaluates them in Velox, runs the equivalent Flink SQL in Flink, and
compares the results. Flink Query Runner is designed to run against Flink-1.19.

How It Works
------------

Since Flink 1.16, the Flink SQL Gateway exposes a REST API that executes SQL
statements in a Flink session and returns results as JSON. The Flink Query
Runner submits queries and fetches results through it. The steps for this
process are as follows:

1. Open a Flink session through ``POST /v1/sessions``. The session runs queries
   in batch mode with ``table.local-time-zone`` taken from the Velox query config
   ``session_timezone`` (UTC if not set, as in Velox), so that Flink runs the
   queries with the same timezone as Velox.
2. Convert the Velox plan, a projection over the fuzzer-generated input rows,
   into Flink SQL. The input rows are inlined as typed literals in a ``VALUES``
   clause, so the Flink cluster does not need to read files written by Velox,
   e.g.

   .. code-block:: sql

       SELECT (`c0` IS TRUE) AS `p0`, `row_number` AS `p1`
       FROM (VALUES (CAST(TRUE AS BOOLEAN), CAST(0 AS BIGINT)),
                    (CAST(NULL AS BOOLEAN), CAST(1 AS BIGINT)))
           AS t(`c0`, `row_number`)

   Velox function names are mapped to Flink SQL syntax where they differ, e.g.
   ``is_true(x)`` to ``x IS TRUE`` and ``ltrim(s, c)`` to
   ``TRIM(LEADING c FROM s)``. Expressions that have no Flink counterpart, e.g.
   ``try``, are reported as unsupported and are not verified.
3. Submit the statement through ``POST /v1/sessions/{session}/statements``.
4. Fetch the results through
   ``GET /v2/sessions/{session}/operations/{operation}/result/{token}?rowFormat=JSON``
   until the end of the stream.
5. Convert the JSON rows into Velox vectors of the plan output type for the
   comparison with Velox's results.

If Flink rejects a query while parsing or validating it, e.g. because a
function does not accept the argument types, the query is reported as
unsupported instead of failed, so that gaps of the SQL translation do not show
up as mismatches.

Usage
-----

To use the Flink Query Runner, you will need to deploy an executable Flink and
start a local cluster and the SQL Gateway with below command.

.. code-block::

    export FLINK_HOME=/path/to/flink-1.19.2
    bash scripts/flink/start-flink.sh

The gateway is started at `http://localhost:8083`. Then run the fuzzer with
Flink as the reference database.

.. code-block::

    _build/release/velox/experimental/stateful/fuzzer/flink_expression_fuzzer_test \
        --flink_gateway_url=http://localhost:8083 --duration_sec 600 \
        --logtostderr=1 --minloglevel=0

Without ``--flink_gateway_url``, the fuzzer only compares the results of the
Velox evaluation paths with each other.

``cast`` is not among the special forms generated by default, as Velox casts
follow Presto semantics while Flink casts follow Flink's. Pass
``--special_forms=and,or,cast,coalesce,if,switch`` to include it.

The Flink Query Runner is tested by ``velox_flink_query_runner_test``, which
requires the SQL Gateway (set ``FLINK_GATEWAY_URL`` if it is not at
`http://localhost:8083`) and is therefore disabled in CTest. The SQL
translation is tested by ``velox_flink_sql_test``, which runs without Flink.

Nightly Run
-----------

``.github/workflows/flink-fuzzer.yml`` builds the fuzzer, starts Flink with
``scripts/flink/start-flink.sh`` and runs the fuzzer against it for an hour
every night. It can also be started manually with a ref, duration and seed.
Failures are reported as GitHub issues labeled ``flink-fuzzer`` by
``scripts/flink/fuzzer-report.sh``: the issue title holds the failure reason,
and a failure whose reason matches an open issue is added to it as a comment.
The issue links to the run artifacts, which contain the repro files and the
tail of the fuzzer log, and gives the seed to reproduce the failing iteration.

Limitations
-----------

* Interval types are not supported yet, so the interval arithmetic and
  comparison functions are not verified against Flink.
* ``to_timestamp_ltz`` is skipped, as Flink returns ``TIMESTAMP_LTZ`` while
  Velox returns a ``TIMESTAMP`` holding the UTC instant.
* ``json_value`` is skipped, as its integer arguments encode the
  ``RETURNING`` type and the ``ON EMPTY`` / ``ON ERROR`` behaviors of the Flink
  plan.
* Functions that read the current time, e.g. ``current_timestamp``, are skipped
  as they are not deterministic.
